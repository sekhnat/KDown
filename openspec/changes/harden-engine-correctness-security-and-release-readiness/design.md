# Design

## Context

See `proposal.md` and the six delta specs for the behavioral contract. At HEAD `0050ebb`, `.github/workflows/ci.yml` runs `cargo build/test/clippy --workspace --all-targets` on Ubuntu, macOS, Windows using Rust `1.98.1`; docs and Linux-only benchmark smoke also run. Workspace metadata says `rust-version = "1.85"`, but the root `Cargo.lock` is ignored and no MSRV job exists; this machine has only distro Rust `1.98.1` (no `rustup`), so support for 1.85 has not been established here. [CI run 36172416772](https://github.com/sekhnat/KDown/actions/runs/36172416772) confirms Windows E0599 at `io/positional.rs:241`: a test uses `File::read_exact_at`, defined only by its `#[cfg(unix)] ReadExactAt` extension. That run and its predecessor fail on macOS in `runtime_control_tests::h1_adaptive_reverts_when_marginal_gain_disappears` at the assertion requiring reversion to one; the logs do not establish *why* reversion is missed. Linux, docs, and bench smoke pass.

`DownloadRequest::Debug` masks `authorization` but prints its `headers` vector verbatim. `http::transport::RequestSpec` derives `Debug` including headers, as do `http::execution::{ProbeRequest, TransferRequest}`; `http::scripted` formats headers in expectation/mismatch descriptions and call records. `redact.rs` has a known-sensitive-header-name list for other purposes, insufficient for arbitrary caller credentials. `DownloadHandle::set_concurrency` invokes `SegmentedJob::set_desired_workers` (which clamps and enables manual override) and emits `RateLimitChanged { bytes_per_second: None }`; `set_rate_limit` emits that event *before* updating its bucket. `control::rate_limit::RateLimiter::acquire` overwrites an earlier wait with any later `Some`, whereas `job/{controller,segmented}.rs` separately calculate `max(job_wait, global_wait)` and select cancellation while sleeping. The controller implementation and root re-export are currently named `SingleStreamController`, though it starts both transfer modes. CI already calls `scripts/bench_check.sh --smoke` and explicitly avoids workstation baseline thresholds.

## Goals / Non-Goals

**Goals:** Small, auditable fixes with deterministic regression tests; preserve current token accounting, event-stream delivery conventions, controller construction methods, platform behavior, and existing smoke/regression evidence. Verify claims against the declared MSRV and all supported OS runners.

**Non-Goals:** New network protocols, changing the adaptive algorithm merely to please a flaky test, a scheduler/checkpoint rewrite, higher absolute benchmark scores, new dependencies/unsafe for simple portability fixes, or global logging/URL-redaction policy changes unrelated to request-header leakage.

## Decisions

1. **Repair the actual CI failures, retain coverage.** Replace the Unix-only *test read-back* with a portable post-write read (e.g., seek/read on a private file handle, or platform-specific `FileExt::seek_read` behind `cfg(windows)`); do not replace production positional writes with shared-cursor writes. Retain short-write, offset-check, disjoint-write, and large-offset coverage; extend a narrow Windows test for real positional read-back, using sparse/limited reads for >4 GiB where runner storage permits. For macOS, reproduce `h1_adaptive_reverts_when_marginal_gain_disappears` with `--nocapture` and targeted state/fixture instrumentation, compare desired-worker history, per-connection delays, measured goodput windows, and end-of-transfer timing against deterministic `control/adaptive.rs` tests. If the fixture's claim of always-harmful added connections is false or observation misses an event, repair the fixture/observation with controlled synchronization and preserve a deterministic policy-level reversion test; if the policy truly fails, fix the policy and add a regression. Do not ignore/skip the test or loosen its byte-exactness assertion. Keep named matrix steps and failure logs; test on hosted macOS and Windows after the fix, not just Linux.

2. **Verify MSRV against a reproducible dependency graph.** Run workspace/all-target `cargo check` (and relevant tests if viable) using *exactly* Rust 1.85 on a CI runner with an explicitly selected toolchain; include examples/bench targets as appropriate. Normal CI continues to use the pinned `rust-toolchain.toml` 1.98.1 (explicit installation in the existing matrix). Because the root lockfile is currently ignored, make the intended dependency set reproducible for CI (prefer tracking a reviewed workspace `Cargo.lock` with a narrow `.gitignore` exception, especially if the current resolution is incompatible with 1.85; verify `--locked` succeeds on both toolchains). For a library, keep dependency constraints compatible with actual consumers and document that an app's own lockfile can resolve differently. First test 1.85 against the intended graph; if newer source/dependency requirements are intentional and cannot be safely constrained, establish the lowest viable Rust release by testing candidate versions, update workspace `rust-version`, CI, README, and changelog together. Never silently turn the MSRV job into a 1.98 check or remove needed security updates. Keep docs/build/test/clippy/benchmark smoke checks; add a formatting check if absent.

3. **Centralize safe diagnostic formatting of header collections.** Add a narrow formatting helper for `&[(String,String)]` that exposes only header names and fixed placeholders (never formats values); use it in `DownloadRequest` and `RequestSpec` debug and request wrappers via nested formatting. Review scripted expectation descriptions, mismatch/error messages, and call-record debug/logging: mask any caller-supplied header values at formatting time without changing matching or the stored values used for tests. Retain existing authorization/provider masking; inspect `ProxyConfig`/connector debug for proxy credentials as well. Keep the current `Redactor` URL/query and known-sensitive-name policy for their existing purposes; do not rely on that list for the new header policy. Test exact unique sentinels for known and unknown names in debug and error/log surfaces. Consider separately whether diagnostic URLs contain credential strings; avoid adding any new path that prints them.

4. **Emit accurate, ordered runtime events.** Add `Event::ConcurrencyChanged { workers: u64 }` with rustdoc matching `desired_workers`' type. Preserve `set_concurrency` as a sync method and its no-op behavior before a segmented job exists; apply clamp/manual override first, then emit exactly one concurrency event with the applied count, never a rate event. Make the applied value available at the update boundary rather than re-reading after a concurrent call; serialize manual control update+event emission if needed so two concurrent callers' events cannot be inverted, without holding scheduler or sink locks across user callbacks. Since `EventHub::emit_try` is nonblocking, this is a bounded control operation. Apply `set_rate_limit` to its stable bucket before emitting its existing `RateLimitChanged` value (`None` for zero), preserving pre-start and live behavior. Test via subscribed `EventStream`; bound timeouts and filter incidental lifecycle events, then assert no cross-kind event from each isolated call. Internal adaptive adjustments do not masquerade as manual change events.

5. **One authoritative wait combiner, not two debits.** Fix `RateLimiter::acquire` to aggregate optional waits using `max`, counting bytes exactly once in each applicable bucket. Wire sequential and segmented acquisition to this single combiner (or a small shared helper used by `RateLimiter` and both hot paths); keep their existing `tokio::select!` around the resulting delay and cancellation token. Prefer the existing fast unlimited check and shared `Arc<TokenBucket>` instances; do not create new buckets per chunk or call `acquire` twice. Extract a pure wait-combination test seam so unequal/equal/None cases are deterministic; add bucket-level integration tests confirming the slowest gate and debit behavior, and cancellation tests for both paths. Existing throughput semantics otherwise stay unchanged.

6. **Rename once, alias rather than fork.** Rename the struct and inherent impl to `DownloadController` in `job/controller.rs`, re-export it from the root (and keep the existing module path). Add a deprecated public `type SingleStreamController = DownloadController` in the old module and re-export it at the crate root, with migration message and rustdoc. Keep methods/constructors only on the canonical struct. Convert internal/tests/examples/README/rustdoc to the canonical name; use a targeted compile-level compatibility test with local `allow(deprecated)` so the CI `-D warnings` lint still detects accidental deprecated use elsewhere. If an alias demonstrably cannot preserve construction in a supported compiler, document the breaking fallback explicitly before release.

7. **Document facts, not transient plan IDs.** In touched files and `job/controller.rs`, `job/segmented.rs`, core `control` modules, replace task-number-only or bare `§` comments with self-contained safety/durability/race explanations; retain useful normative links only alongside rationale. Extend README and `docs/benchmark-profiling.md` with the scope of existing local loopback baselines and variables affecting WAN performance, preserve existing records and current CI smoke policy. Add an Unreleased changelog section covering tested fixes, MSRV decision, and compatibility migration only after verification.

## Risks / Trade-offs

- [Windows sparse file/read-back and rename behavior differs from Unix] → Use a platform-safe test read after writes on an isolated handle and run the actual Windows CI suite; do not infer success from cross-compilation alone.
- [Mac failure may reflect a genuine adaptive-policy bug or non-deterministic fixture/observation] → Instrument and reproduce the exact failing scenario on macOS, validate the fixture's premise before changing policy, retain independent deterministic policy and end-to-end coverage.
- [Unpinned resolution defeats MSRV coverage or a new lockfile constrains library development] → Check exact compiler+locked graph in CI, keep direct dependency constraints sane, refresh the lockfile deliberately and state the library-consumer caveat.
- [Broad masking reduces diagnostics and scripted assertion detail] → Preserve header names and mismatch context without values; keep raw values available for request matching, never in formatted diagnostics.
- [Concurrent control calls can reorder observed events] → Keep state-update+emission ordering at the control boundary and test applied/clamped values; do not hold locks while sending through application callbacks.
- [Combining two live buckets can change interleaving under contention] → Preserve per-bucket debit order/count and negative-balance semantics, verify cancellation and existing throughput tests; only arbitration changes.
- [Deprecated alias warns under `-D warnings`] → Migrate all project code; isolate compatibility test under `allow(deprecated)`.

## Migration Plan

Make fixes in small, test-backed slices (platform diagnosis; redaction; events; rate arbitration; alias; docs), then run formatting, workspace check/build/test/clippy and doc checks, benchmark compile/smoke, and the dedicated MSRV job. Check Linux/macOS/Windows hosted CI at the final commit before declaring release ready. Existing controller imports remain working through the deprecated alias; advise migration to `DownloadController`. Roll back individual fixes if they regress invariants, but do not ship a partial release claiming green CI or a tested MSRV.
