# Design

## Context

See [proposal.md](proposal.md) for motivation and [specs/download-destination-resolution/spec.md](specs/download-destination-resolution/spec.md) for behavior. Today `DownloadRequest` is an exhaustively constructible public struct, while `DownloadController::start` spawns one `run_inner` pipeline that leases the explicit destination and begins checkpoint admission before `HttpExecution::probe`. `http::probe::ProbeMetadata` carries a single `filename_hint` extracted by a simplistic parser; HEAD header values currently use `to_str().unwrap_or("")`; `io::sanitize_filename` has a fallback-returning sanitizer with a 255-byte cap. Temp outputs append `.part`; the destination lease uses both process-local ownership and persistent cross-process lockfiles. `resume::flow::begin_admission` treats absence as an error for Required; checkpoint resolver contexts are keyed by URL plus destination. `Event` is already non-exhaustive. `openspec list --specs` reports no main capabilities. Relevant regression seams: `crates/engine/tests/{external_consumer_fixture,publication_tests,checkpoint_seam_tests,resume_tests,platform_fs_tests,handle_control_tests}.rs`, internal HTTP tests and `fuzz_targets.rs`.

## Goals / Non-Goals

**Goals:**
- Integrate destination resolution into the existing controller, checkpoint admission and commit paths rather than build a second downloader.
- Establish one immutable destination/identity under a held lease, with explicit before-network and directory after-probe ordering called out in code/tests.
- Keep new naming logic internal and additive at the crate root, and preserve old file API/behavior without blanket sanitization of caller paths.

**Non-Goals:**
- Protect against a malicious actor replacing entries in the caller's trusted directory; lexical containment and atomic no-replace are the promised boundaries.
- Name changes based on a validating GET or transfer response; extend the public HTTP probe seam; consume probe response bodies; add a naming error category.

## Decisions

### 1. Represent the two target modes without modifying `DownloadRequest`

Add a public `DirectoryDownloadRequest` holding an ordinary `DownloadRequest` plus private fallback and byte limit. Provide `new(url, directory)`, `request_mut()`, and builder methods for fallback/cap, then add `start_to_directory`, `run_to_directory`, `run_to_directory_with_handle`. Store the directory separately from the eventual file destination in a private target enum passed into one private start/run pipeline. Validate options/directory at job start before the probe, because `request_mut()` can change overwrite/resume after construction. After resolution set the owned request's destination to the selected final path and reuse the existing request-dependent sink, error, cleanup, transfer and publish operations. Do not add a field to `EngineConfig` or `DownloadRequest`, or change signatures of `run/start/run_with_handle`. Alternative: a new request field or overload old methods; rejected because public struct literals and method references would break and an explicit file path might be misclassified as a directory.

### 2. Preserve ordered probe hints and decode only the required header

Extend internal `http::probe::ProbeMetadata` with an ordered plain-filename fallback beside the existing `filename_hint` (or equivalent ordered internal representation). Parse only the first HEAD Content-Disposition with a bounded state machine: track quoted strings and quoted-pair escapes across semicolons, accept tokens, retain the first well-formed `filename*` and `filename` separately; validate extended UTF-8/percent escapes strictly. Preserve `filename_hint` behavior where existing tests rely on it; resolve candidates after sanitization in the controller, not while parsing. In `http::transport::run_headless` decode only Content-Disposition using `String::from_utf8_lossy` to allow ordinary raw non-UTF-8 filename bytes; leave unrelated header conversion alone. The validating GET remains body-free metadata validation, and HEAD metadata remains authoritative even if that GET redirects. Extract URL path through the existing URI representation; take the final segment only, exclude query/fragment, decode percent escapes once and reject decoded separators. Alternative: pick a single hint inside `probe` or parse all response headers in the controller; rejected because one hint loses a sanitized-away extended value's plain fallback, and controller must not handle raw HTTP responses.

### 3. One portable, fallible basename sanitizer and suffix-aware truncation

Extend `io::sanitize` with `try_sanitize_filename(input, byte_limit) -> Option<String>` for candidate fallthrough and keep `sanitize_filename` as the fallback-returning wrapper. Normalize header separators before selecting the final component; replace forbidden punctuation character by character, strip controls, trim trailing Windows-invalid characters, prefix Windows device stems (including superscript COM/LPT variants), truncate on UTF-8 boundaries with best-effort extension preservation, then revalidate the normal-component and device-name invariants. Validate the fallback against *unchanged* fallible output; reject invalid caps including Rename's 7-byte minimum before network. Enforce min(configured cap, 250) for directory names, preserving five bytes for `.part`; build `directory.join(component)` only after validation. For generated Rename siblings reserve ` (n)` bytes first and then truncate stem/extension; explicit-file base remains verbatim if free, while generated siblings must meet `.part` headroom and safe-representation checks. Alternative: use the current 255-byte wrapper for every candidate; rejected because it turns invalid hints into a winning `download`, loses suffix uniqueness and leaves no `.part` headroom.

### 4. Separate preparation order, converge on existing downstream execution

Factor the current `run_inner` preparation into a shared probe phase and destination-admission helper with an owned lease, store and pending admission. For explicit files, retain FailIfExists precheck and lease → identity/resolver → begin_admission → probe; for file Rename, perform candidate selection and the same admission before probe. For directory requests, perform request/directory validation → existing probe loop (including retry/auth/origin/cancellation/deadline) → resolve/lease final filename → identity/resolver/begin_admission → finalize with the *already obtained* validators. Both paths rejoin at `pending_admission.finalize`, size check, transfer and atomic publish; no second probe after selection. Map Rename to `PublishMode::NoReplace`, keep other policy modes. Keep lease and selected store alive through cleanup/commit, not just selection. Avoid mutating destination before the pre-lease probe in directory mode; preserve legacy event sequence by emitting the new event only for opted-in modes. Alternative: re-run probe after choosing a directory name; rejected for duplicate network/auth activity and possibly changed metadata/identity.

### 5. Resume-first Rename search under candidate leases

Use one bounded candidate iterator (base, 1..=999) for file and directory Rename, with suffix-aware naming. If resume is enabled, first consider only candidates with a plausible partial/checkpoint (cheap existence checks for default sidecars; avoid lockfiles for obviously absent candidates); skip occupied finals and lease conflicts; under each acquired lease build that candidate's identity/resolver and use a crate-private `resume::flow` discovery variant of `begin_admission` that distinguishes *absent* from an admitted pending checkpoint without parsing error strings. Preserve existing Allowed corrupt-state deletion/fatal cleanup and Required error policy. A structurally admitted candidate wins even over a free earlier name. Keep its lease, `Arc<dyn CheckpointStore>` and pending admission together so they are neither loaded nor admitted twice; finalize only after the single probe. For fresh selection, inspect final and `.part` with `symlink_metadata`, acquire the nonblocking lease, then recheck both entries under lock; skip only DestinationConflict and propagate other lease errors. Do not open/truncate a stale `.part`. Exhaustion yields DestinationConflict except Required without admitted state yields Checkpoint. Atomic no-replace at commit is the final guard against non-cooperating writers. Existing lockfiles are persistent and may be created by attempted acquisitions; limit unnecessary lockfile creation in the discovery pass. Alternative: take the first free basename before inspecting checkpoints or test `Path::exists` without a lease; rejected because it breaks resumed retries and ignores dangling symlinks/races.

### 6. Observe the chosen name without changing terminal semantics

Add `Arc<OnceLock<PathBuf>>` to the handle/start task: initialize immediately only for known explicit-file non-Rename destinations; for opted-in targets set only after acquiring the selected lease, then emit `Event::DestinationResolved { path }` exactly once before transfer progress. `resolved_destination() -> Option<&Path>` returns a stable borrowed path after publication. Preserve existing `Event::Committed` and `CompletedDownload.final_path`. Avoid raw header/URL logging; document that a resolved *path* may reveal server metadata and is deliberately exposed, and do not repeat the current `CheckpointResolveContext` claim that paths are secret-free. Alternative: rely on broadcast alone; rejected because lagging subscribers can miss the event.

## Risks / Trade-offs

- [Directory probe precedes lease/checkpoint validation] → Explicit-file paths remain pre-network; document directory's intentional relaxation, verify probe failures/cancellation create no output artifacts, and do not re-probe during selection.
- [Rename may scan 1,000 candidates and leave lockfiles] → Limit scan, skip obviously absent resumable candidates before leasing, document cost and persistent lockfile behavior; do not weaken cross-process protection.
- [Selection TOCTOU with uncooperative writers] → `symlink_metadata` both before/under lease and atomic no-replace at commit; report DestinationConflict on late races rather than silently renaming again.
- [Unicode/portable filename corner cases] → Re-check after truncation/suffixing; fuzz path containment and run publication tests on macOS and Windows in CI, not just one platform.
- [Existing integration tests assume early admission] → Protect old paths with external-consumer, event-order and pre-network test cases before rearranging controller logic.

## Migration Plan

Ship additive root exports and `Rename` as opt-in; old callers need no code or checkpoint migration. Update `docs/api-surface.md`, `docs/api-compatibility.md`, `CHANGELOG.md`, inventory script and consumer fixture together. A rollback can remove the new opt-in entry points and policy from the unshipped release; after external adoption, retain supported symbols and use a corrective release instead. Checkpoint identity stays URL+selected path and sidecar layout remains unchanged, so existing explicit-file checkpoints remain readable.
